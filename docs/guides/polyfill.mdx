---
title: Browsers without WebMCP
description: The polyfill gives any browser document.modelContext, including declarative form tools, so you can build and test agent-ready pages today.
---

Native WebMCP is only in Chrome, behind an origin trial. `@webmcp-agents/polyfill` provides the same
`document.modelContext` everywhere else, so pages, devtools and the chat work in any browser while you build. It steps
aside when the browser has the real API.

```bash
pnpm add -D @webmcp-agents/polyfill
```

```ts
if (import.meta.env.DEV) {
  await import("@webmcp-agents/polyfill/auto");
}
```

Import it before your app renders, so it exists when the first tool registers. Or install it explicitly:

```ts
import { installWebMCPPolyfill } from "@webmcp-agents/polyfill";

const modelContext = installWebMCPPolyfill();
```

## What it covers

- `registerTool(tool, { signal })`, `unregisterTool(name)`, `getTools()` and `executeTool(nameOrTool, args, { signal })`.
  `executeTool` accepts both its own `(name, object)` shape and Chrome's `(tool, JSON string)`.
- Lifecycle events on `document.modelContext`: `toolchange`, `toolactivated` and `toolcancel`.
- **Declarative forms**, found with a MutationObserver: the input schema from the controls, `toolautosubmit`, and the
  confirmation pause.
- `SubmitEvent.agentInvoked` and `respondWith(promise)`.
- A non-standard `cancelTool(name)`, so the devtools can cancel a call they didn't start.

## Differences from Chrome

| | Chrome | Polyfill |
|---|---|---|
| Form states | `:tool-form-active`, `:tool-submit-active` | `[data-tool-form-active]`, `[data-tool-submit-active]` (a script can't define pseudo-classes) |
| Event order | fill → `submit` → `toolactivated` | `toolactivated` → fill → `submit` |
| Cancelling another caller's call | not possible | `cancelTool(name)` |

`@webmcp-agents/core` handles both orders, and `cursor.css` styles both kinds of state, so the same code and stylesheet
work on either.

## In production?

The example apps load the polyfill in development only, so a deployed demo shows no tools in a browser without native
WebMCP. Shipping it to production is your call: it lets your own chat widget work everywhere, but browser agents
that don't know about it won't see its tools.
