[WebMCP](https://developer.chrome.com/docs/ai/webmcp) lets a page hand an AI agent a set of **tools**:
"search flights", "add to cart", "place order". The browser exposes them on `document.modelContext`, and an agent
(a browser assistant, a chat on your site, a model on the device) calls them instead of guessing at pixels.

That leaves the person using the page with a problem: **things happen and they can't see why.** A field changes on
its own. The cart fills up. An order is one call away from being placed.

`webmcp-agents` makes every one of those calls visible and keeps the person in charge:

*The agent adds a tee to the cart: the ghost cursor flies to the form, types the values, clicks, and the cart drawer opens.*

- **A ghost cursor** glides to the tool the agent is using, types its values into the real fields, and clicks, so the
  page reacts at the moment it looks like it should.
- **A parked "confirm" state.** For anything consequential (orders, bookings, deletions) the cursor stops on the
  button and waits. Only the person's own click goes through.
- **The person always wins.** The moment they move the mouse, scroll or type, the cursor gets out of the way and the
  tool finishes without the animation.
- **Your tools don't change.** They never import the visual layer. The only link between a tool and its cursor is a
  `toolname` attribute on the element it acts on.

:::note[WebMCP is still a preview]
WebMCP ships in Chrome behind an origin trial, and its shapes still move between versions. `webmcp-agents` absorbs
those differences (event targets, `executeTool` argument shapes) so your code doesn't have to. In any other browser,
the [polyfill](/guides/polyfill) provides the same API for development.
:::
