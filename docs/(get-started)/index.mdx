With [WebMCP](https://developer.chrome.com/docs/ai/webmcp), a page hands an AI agent **tools** it can call: "add to
cart", "place order". WebMCP Agents makes every call visible to the person on the page: a ghost cursor flies to the
control, types the agent's values into the real fields, and stops for a real click on anything that matters.

## A tool is one function with two callers

You already have the function. A person clicks the button; an agent calls the tool.

```tsx
// An agent calls this.
useWebTool({
  id: "clear_cart",
  title: "Clear cart",
  description: "Empty the cart. The user confirms on the page.",
  requireConfirmation: true,
  execute: clear,
});

// A person clicks this.
<Button onClick={clear}>Clear cart</Button>
```

Nothing is added to the button for the cursor: it finds the control by its name, like a screen reader would. With
`requireConfirmation` it parks there, and `clear` runs only after the person's own click.

:::note[WebMCP is still a preview]
WebMCP ships in Chrome behind an origin trial, and its shapes still move between versions. WebMCP Agents absorbs
those differences, so your code does not have to. In any other browser, the provider loads a
[polyfill](/more/polyfill) of the same API by itself.
:::
