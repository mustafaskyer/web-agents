TanStack Start is a Vite-based full-stack framework, so the client side is the [Vite](/frameworks/vite) setup and the
server handler is a server route in the same route tree. There is no example app for it in this repository; the
snippets below are the complete shape. The server-route API moved between Start releases
(`createServerFileRoute` → `createFileRoute(...).server.handlers`), so check the version you install.

## 1. Install

```bash
pnpm add @webmcp-agents/core @webmcp-agents/react @webmcp-agents/chat
pnpm add -D @webmcp-agents/polyfill @webmcp-agents/devtools        # development only
pnpm add @ai-sdk/anthropic                                         # the SDK of your model's provider, server only
```

## 2. Styles and the polyfill

Start renders on the server and hydrates on the client: import the stylesheets in the root route, and load the
polyfill only in the browser, before the provider mounts.

```tsx src/routes/__root.tsx
import cursorCss from "@webmcp-agents/core/cursor.css?url";
import chatCss from "@webmcp-agents/chat/chat.css?url";
import { createRootRoute, HeadContent, Outlet, Scripts } from "@tanstack/react-router";

export const Route = createRootRoute({
  head: () => ({
    links: [
      { rel: "stylesheet", href: cursorCss },
      { rel: "stylesheet", href: chatCss },
    ],
  }),
  component: RootDocument,
});

function RootDocument() {
  return (
    <html lang="en">
      <head>
        <HeadContent />
      </head>
      <body>
        <App />
        <Scripts />
      </body>
    </html>
  );
}
```

## 3. Tools and the agent

The same files as in any React app: plain definitions with no DOM access, so the agent is importable by the server
route too.

```ts src/tools/catalog.ts
import { defineWebTool } from "@webmcp-agents/react";

export const getCart = defineWebTool({
  id: "get_cart",
  description: "Read the cart: lines, promo code and totals.",
  annotations: { readOnlyHint: true },
  execute: (_input, ctx) => ctx.context!.cart.describe(),
});

export const catalog = [getCart];
export const globalTools = catalog.map((t) => t.id);
```

```ts src/agents.ts
import { defineWebAgent } from "@webmcp-agents/chat/agent";

export const shopper = defineWebAgent({
  id: "shopper",
  instructions: "Field Store sells apparel, accessories and home goods. Open a product before adding it.",
});
```

## 4. The provider and the chat

`useLocation()` from TanStack Router feeds the provider's `pathname`. The polyfill and the devtools load in an effect
(client only); the provider renders once they are in place.

```tsx src/routes/__root.tsx (the App component)
import { AgentChat, createCloudAdapter } from "@webmcp-agents/chat";
import { WebAgentsProvider } from "@webmcp-agents/react";
import { Outlet, useLocation } from "@tanstack/react-router";
import { useEffect, useState } from "react";
import { shopper } from "~/agents";
import { catalog, globalTools } from "~/tools/catalog";

const ADAPTERS = [createCloudAdapter()];

function App() {
  const { pathname } = useLocation();
  const [ready, setReady] = useState(false);
  useEffect(() => {
    void (async () => {
      if (!document.modelContext) await import("@webmcp-agents/polyfill/auto");
      if (import.meta.env.DEV) (await import("@webmcp-agents/devtools")).installWebAgentsDevtools();
      setReady(true);
    })();
  }, []);
  if (!ready) return <Outlet />;
  return (
    <WebAgentsProvider tools={catalog} global={globalTools} pathname={pathname}>
      <Outlet />
      <AgentChat adapters={ADAPTERS} agent={shopper} />
    </WebAgentsProvider>
  );
}
```

## 5. `/api/chat` as a server route

The handler is a web-standard `(Request) => Promise<Response>`, so the server route hands it the request.

```ts src/routes/api/chat.ts
import { createFileRoute } from "@tanstack/react-router";
import { createChatHandler } from "@webmcp-agents/chat/server";
import { shopper } from "~/agents";

const handler = createChatHandler({ agents: [shopper] }); // reads process.env on the server

export const Route = createFileRoute("/api/chat")({
  server: {
    handlers: {
      GET: ({ request }) => handler(request),
      POST: ({ request }) => handler(request),
      OPTIONS: ({ request }) => handler(request),
    },
  },
});
```

```bash .env.local
WEB_AGENTS_MODEL=anthropic/claude-opus-5-5
ANTHROPIC_API_KEY=sk-ant-…
```

A public deployment needs a guard with rate limits and a budget: `createChatHandler({ guard, beforeModel })`, or
`@webmcp-agents/vercel-api`'s `createVercelChatRoute` when deploying to Vercel.

## 6. Development

Start's dev server serves the server route, so no Vite plugin is needed for `/api/chat`. You can still add
`webAgentsChatDev()` to the Vite plugin list for its secret guard (it refuses to start when a `VITE_*` variable is
named like a secret); set its `path` to something unused so it never shadows the real route.

## Where secrets live

| | |
|---|---|
| The API key | `process.env` on the server (`.env.local`, unprefixed). Only `VITE_*` reaches the client, as in any Vite app. |
| The model | `WEB_AGENTS_MODEL` on the server, or `model` in the handler. |
| Agent instructions | `src/agents.ts`, shared; the server reads them from its registry, the page sends only the id. |
